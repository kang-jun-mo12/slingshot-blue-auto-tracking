# 현재 자동추적 보정 (2026-10-08, 재검증)

전체 격자 사진 2,135장에서 3,443개 사진 쌍, 558,038개 특징점 이동을 추출했습니다.
부분 촬영 세션도 포함했습니다. 새 좌우 계수는 사진 쌍 단위 분리 검증을 통과해
`tracking-prior.json`에 반영했고, 검증 오차가 큰 새 상하 계수는 적용하지 않았습니다.
상하는 기존 검증 계수와 실제 자동추적 응답을 사용합니다.

`tracking_sessions`의 원본 사진·적용 각도·검출 결과를 기준으로 피드백을 재구성했습니다.
최근 4회 실추적의 이동 전후 28쌍을 모두 검토했으며, 반응 없는 명령도 버리지 않습니다.
검출 중심 변화는 사진의 배경 특징점 이동과 대부분 1~2px 이내로 일치했습니다.
따라서 큰 오차는 박스 중심의 흔들림보다는 실제 카메라 움직임에 있었습니다.

큰 이동과 미세 이동을 크기별로 나눠 반영하며, 같은 실행에서 관측한 중심 양쪽 위치를
이용해 미세 보정의 범위를 줄입니다. 반복해서 확인된 정지·급이동 구간에서는 명령을
누적하지 않고 관측을 계속합니다. 실제 장비에서 이동 후 늦게 추가 이동하는 사례가
있어 촬영 전 안정화 대기는 최소 3초로 늘렸습니다. 0.1°는 명령 분해능이며 실제 축의
0.1° 정확도를 뜻하지 않습니다. 중앙 목표 기준(축별 3px / 거리 4px)은 유지하되,
해당 기준에 도달하지 못한 상태를 중앙 맞춤 성공으로 표시하지 않습니다.

시작 각도는 0~180°입니다. 기존 측정 범위 밖에서는 가장 가까운 보정값과 최대 3° 이동,
범위 안에서는 최대 8° 이동을 사용합니다. 총 8회 관측하고 최소 오차가 관측된 각도로
복귀합니다. 최종 각도에서 직접 촬영한 값과 복귀 전의 최저 오차 기록은 구분해 표시합니다.

실제 기록을 실행 단위로 제외하는 교차 검증에서 이동량 예측 평균 오차는
34.73→28.33px, 90백분위는 55.73→48.66px였습니다. 이는 최종 중심 오차와 다른 지표입니다.

- `calibration/all-data-20261008/`: 전체 사진 후보 계수·사진 쌍·특징점 자료
- `calibration/tracking-prior.json`: 검증을 통과한 축 선택 및 원본 계수 해시
- `tracking_sessions/feedback-v2.jsonl`: 원본 관측에서 재구성한 이동 자료
- `diagnostics/tracking-model-validation.json`: 실행별 분리 검증
- `diagnostics/tracking-motion-20261008.json`: 박스 중심과 배경 이동 비교
- `diagnostics/candidate-tracking/`: 실제 장비 시험과 별도 복귀 확인 사진 결과

복구된 과거 최종 상태 3건은 연속 이동 정보가 없어 이동량 학습에는 사용하지 않습니다.
각도가 기록되지 않은 단일 사진도 이동량을 임의로 부여하지 않습니다.
아래는 기존 초기 보정 기록이며 현재 시작·종료 조건이 아닙니다.

# 기존 픽셀·서보 각도 보정 기록

현재 카메라 장착 상태가 기존 촬영 때와 같다는 사용자 확인을 바탕으로,
2026-09-28에 저장한 3개 촬영 세션(각 168장, 총 504장)을 분석했습니다.
좌우 30~150°, 상하 90~110° 구간의 3° 격자를 포함합니다. 마지막 상하 간격은 108→110°입니다.

이는 1920×1080의 모든 픽셀을 하나씩 물리적으로 전수 측정한 자료가 아닙니다.
실제 각도별 사진의 동일 특징점 이동을 측정해 화면 전체에서 계산하는 보간 모델입니다.
카메라 방향·장착·화각·해상도가 바뀌면 다시 측정해야 합니다.

## 측정 방법과 결과

- ORB 특징점 대응과 RANSAC으로 정지 배경의 움직임을 측정했습니다.
- 최소 25개 대응점, 60% 이상 일치율, 화면 내 가로 500 / 세로 250 px 이상 분포를 요구했습니다.
- 사진 쌍 821개, 특징점 이동 96,853개를 사용했습니다.
- 화면 위치와 현재 좌우/상하 각도에 따른 픽셀/도 변화량을 강건 회귀로 적합했습니다.
- 같은 사진 쌍의 점들이 학습/검증에 동시에 들어가지 않도록 사진 쌍 단위로 약 20%를 분리했습니다.

| 축 | 비교 쌍 | 특징점 | 검증 중앙값 오차 (px/°) | 검증 95백분위 오차 (px/°) |
|---|---:|---:|---:|---:|
| 좌우 | 475 | 59,295 | 2.232 | 6.275 |
| 상하 | 346 | 37,558 | 3.523 | 10.281 |

현재 설치 상태에서 별도로 116°/96°를 기준으로 좌우·상하를 각각 3° 왕복시켜 검증했습니다.
모든 검증 후 원래 116°/96°로 복귀했고 D9는 90°를 유지했습니다.

| 실제 이동 | 대응점 | 예측 위치 오차 중앙값 (px) | 95백분위 (px) |
|---|---:|---:|---:|
| 좌우 116→119° | 217 | 5.07 | 19.78 |
| 좌우 119→116° | 223 | 13.42 | 19.69 |
| 상하 96→99° | 195 | 9.81 | 12.71 |
| 상하 99→96° | 177 | 5.59 | 9.02 |

현재 검증은 이 위치 주변의 왕복 확인이며, 모든 각도에서 같은 정확도를 보장하지 않습니다.
사진 간 유격·왜곡·거리 차이 등이 오차에 포함됩니다. 큰 이동의 오차가 비례해서 작다는 뜻도 아닙니다.
현재 동작은 계산한 목표 각도로 한 번에 이동하고 반드시 새 사진으로 확인합니다.
12°씩 나누는 제한은 제거했으며, 측정된 각도 범위는 유지합니다.
마지막 사진이 중앙 허용 오차(가로·세로 각각 12 px, 중심 거리 15 px) 안에 들어오면 종료합니다.
첫 이동 후 오차가 남으면 최대 8회까지 추가 보정하며, 매번 새 사진으로 확인합니다.
중앙 기준에 도달하면 즉시 종료합니다. 최저 중심 거리보다 2px 넘게 개선되지 않는 관측이
3회 연속이면 반복을 멈춥니다. 횟수 한도 이후에도 마지막 사진으로 확인하고 남은 오차를 표시합니다.
1° 단위로는 더 개선할 수 없는 경우 중앙 맞춤 성공으로 표시하지 않고 분해능 한계로 구분합니다.

## 자료와 재생성

- `calibration/model.json`: 보정 계수, 적용 범위, 검증 통계와 현재 장착 검증
- `calibration/model.npz`: 실제 특징점 측정치 (axis, pair id, x, y, yaw, pitch, dx/degree, dy/degree)
- `calibration/pairs.json`: 원본 세션과 각도별 비교 사진 쌍
- `calibration/current-validation/0.png` ~ `4.png`: 현재 장착 왕복 검증 사진
- `calibration/current-validation/validation.json`: 계수 해시와 실제 검증 결과

기존 사진으로 다시 계산하는 명령 (서보를 움직이지 않음):

```bash
cd /home/kimkangjo/servo-control
OPENBLAS_NUM_THREADS=2 .venv/bin/python build_calibration.py
```

새 계수의 해시가 현재 검증 자료와 다르면 자동 이동을 활성화하지 않습니다.
검증 결과는 `GET /api/calibration`에서 확인합니다.

서버는 미분 이동장을 적분해 목표 위치를 계산하고, 주변 정수 각도 조합 중 오차가 가장 작은 것을
선택합니다. 중간 적분 계산은 모터 명령이 아닙니다. 실제 서보에는 좌우·상하 목표 각도를
한 명령으로 보내며, D9는 현재 적용된 값을 유지합니다.
